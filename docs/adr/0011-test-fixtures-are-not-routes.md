# 0011. Test fixtures are not routes

- **Status:** Accepted
- **Date:** 2026-09-30

## Context

Two sets of GPX files exist in this repository and they look like the same thing. `routes/` holds
rideable routes with a `manifest.json` entry each; `test/fixtures/` holds GPX files used by the
unit tests and by Playwright.

They are not the same thing, and the directory names do not explain why. The obvious and wrong
move — adding a 30 km route to `test/fixtures/` because it is "for testing", or pointing a test
at a bundled route because it is already there — is one a future contributor will make within a
week of not reading this.

The two have opposite requirements. A rideable route has to be long enough to be worth riding:
20 to 30 km, varied terrain, a profile with something in it. A fixture has to be small enough to
hand-compute an expected value from and fast enough to run in a loop.

You cannot assert against a 30 km profile. Nobody can verify by eye what the grade should be at
18,432 m, so any expected value is whatever the code produced the first time it ran — which makes
the test a change detector, not a correctness check. And a Playwright run that has to ride a
route to completion needs that to take seconds.

## Decision

The two sets stay separate, with different rules.

**`routes/`** — bundled rideable routes, GPX plus a `manifest.json` entry giving id, name,
distance, elevation gain and file. The two starting routes are synthetic, generated by a
committed deterministic script in `scripts/` so they are reproducible and tunable, and named
plainly as test routes rather than dressed up as real places. Each exercises a different code
path: Rolling stresses the once-per-second and ≥0.1 % control point write thresholds with
near-continuous grade change; Mixed has the sustained climb that exercises grade clamping and the
descent that reaches the zero-power gravity and drag balance and the 80 km/h cap. Real GPX files
drop in alongside them and need nothing beyond a manifest entry.

**`test/fixtures/`** — small synthetic GPX with exactly computable answers: a 1 km flat, a
constant 10 % climb, a steep descent. These give exact expected values for the physics, grade and
position tests, and let a Playwright run ride a route to completion in seconds. They have no
manifest entry and never appear in the app's route list.

Unit tests use fixtures. The one legitimate exception is the test that checks the generator script
still reproduces the bundled routes byte for byte, which necessarily reads `routes/`.

## Consequences

- Expected values in the physics, grade and position tests are hand-checkable, so a failing test
  means the code is wrong rather than that something moved.
- Playwright rides a complete route in seconds, which is what makes "ride it to completion" a
  test we actually run rather than one we skip.
- Two sets of GPX files is mild duplication, and someone will eventually ask why we do not test
  against the real routes. The answer is above; the generator test is the one place the real
  routes get exercised, and it is deliberately narrow.
- Fixtures are unrealistic by construction. A constant 10 % climb for a kilometre is not a road,
  and nothing about the code's behaviour on real, noisy GPS elevation is proved by them. Real
  routes, the generated ones, and the manual test plan carry that.
- Adding a fixture means asking whether you can still compute the expected answer by hand. If you
  cannot, it belongs in `routes/` and the test needs rethinking.
